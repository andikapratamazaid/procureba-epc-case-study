# ProcureBA: EPC Procurement Digitalization

## A Business Analysis Case Study

**Author:** Andika Pratama Zaid
**Category:** Business Analysis / Data Analytics portfolio project

> **Honest labeling.** This is a fictional case study. The company, people, vendors, and transactions are not real. The dataset is **synthetic**: 2,400 purchase requisition records generated by a Python script with a fixed random seed (42), modeled on typical EPC procurement process patterns (paper PR forms, email RFQs, spreadsheet tracking, maverick urgent buying). Every figure quoted in the documents is a real computed output from that dataset, reproducible by running the analysis. Figures labeled "target" or "estimate" are design targets or case-study planning estimates, not measured results.

## The Case in One Paragraph

A mid-size EPC contractor processes about 1,200 purchase requisitions per year for five project sites through a fully manual process. The analysis shows an average PR-to-PO cycle time of **17.5 days**, a bottleneck in the vendor quotation wait (**6.02 days, 34.4%** of the cycle), and **12.2%** of purchases bypassing the procedure entirely (maverick buying) at a **10.8% price premium**, an estimated **Rp 8.37 billion** of excess spend over two years. The case study maps the problem, proves it with data, and designs the digital replacement: requirements, process maps, prototypes, economics, and an implementation roadmap.

## How to Run

Requirements: Python 3.10 or later. The data generator, KPI engine, and tests use the **standard library only**. Charts, diagrams, the dashboard builder, and the PDF builder additionally use `matplotlib` and `reportlab` (both commonly available; no other dependencies). Everything runs offline.

```bash
# 1. Generate the synthetic dataset (deterministic, seed 42)
python3 data/generate_dataset.py

# 2. Run the analysis: writes output/analysis_results.json and analysis/charts/*.png
python3 analysis/run_analysis.py

# 3. Regenerate all diagrams
python3 diagrams/make_diagrams.py

# 4. Rebuild the KPI dashboard HTML from the analysis results
python3 dashboard/build_dashboard.py

# 5. Rebuild the two PDFs
python3 output/build_pdfs.py

# 6. Run the test suite (11 tests)
python3 -m unittest discover -s tests -v
```

Or open the prototypes directly in a browser, no server needed:

- `dashboard/kpi_dashboard.html`: before (analysis) versus after (simulation targets) KPI dashboard with embedded charts.
- `prototype/workflow_prototype.html`: interactive PR-to-PO simulation with a standard lane and a fast-track lane; state persists in localStorage.
- `wireframes/wireframes.html`: low-fidelity wireframes of the PR form, approval screen, status tracking, and dashboard screens.

## Method Note

The workflow follows a standard business analysis flow: elicitation, as-is process mapping, quantitative analysis, requirements (BRD), gap analysis, solution assessment (build vs buy, cost-benefit), design artifacts (use cases, data model, wireframes), verification planning (UAT and traceability), and implementation planning (roadmap, risks, change management). Requirement IDs (BR, FR, NFR) trace through use cases (UC) and user stories (US) to UAT scenarios (UAT) in the traceability matrix, so every claim in the report can be followed back to data or to a labeled assumption.
